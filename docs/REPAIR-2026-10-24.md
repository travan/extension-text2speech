# Popup, extraction and keyword repair — 2026-10-24

The previous verification did not establish compatibility with arbitrary websites. It mostly exercised the reader in a normal tab and missed the native toolbar entry, build-output collision and real chat markup. This repair adds those checks and records their limits.

## Changes

- Restore Chrome's anchored toolbar popup. Persistent reading in a separate window is explicitly opened with ↗. Bounds are clamped to the source display.
- Give the popup an intrinsic popup size (now 400 × 600 CSS pixels after the UI refresh), set the React root height and scroll only the content region. Using viewport maxima without an intrinsic document size fed Chrome's initial tiny popup viewport back into autosizing. A regression test measured a 25-pixel width before the final fix.
- Give the background entry a unique filename. The generated worker previously could import the content entry when both had the basename index.ts. Verify the built worker listener and production assets.
- Separate development output (.dev-extension) from the installed production build (dist).
- Collect loaded rendered DOM text, including short blocks, mixed article/div content, chat paragraphs, scroll containers and open shadow roots. Preserve semantic article paragraphs together. Stop dropping entire prose lines merely because they mention translation.
- Match exact keywords before removing stop words or single-character tokens. Vietnamese matching remains accent-insensitive.
- Reinject the declared content bundle when an already-open tab has no receiver after extension reload. Report restricted pages and stop waiting after 15 seconds for an unresponsive tab.
- Show distinct empty states for no extracted text and extracted text with no keyword matches. Detail now works for segment ID 0.

The production extension suite checks the real Chrome action popup target via CDP in a disposable headless Chromium profile. It verifies the header/footer/content bounds, clicks Scan and Articles, checks the result, and attaches a popup screenshot plus measured bounds. It also covers hidden text, long article hydration through the final sentence, mixed DOM, short text, translation prose, shadow DOM, missing-receiver recovery, dynamic capture, pagination, session restoration and source-tab isolation.

The first popup harness incorrectly waited for Playwright's page event; Chrome exposed the action popup as an unattached target instead. Those timeout runs were failures, not successful verification. The corrected harness attaches to that target. Earlier failed runs are retained in scan-before-2026-10-24 and popup-layout-2026-10-24.

Public pages: MDN JavaScript, English Wikipedia Artificial intelligence, Vietnamese Wikipedia Trí tuệ nhân tạo, and the Chạm homepage. Each test independently samples up to 12 rendered paragraphs/headings, verifies every sampled full text in the extracted results, and checks that a relevant keyword returns results. This is sampled coverage, not an exhaustive certification of each site.

## Authenticated Chạm check

Using the user's existing Chrome session and the native toolbar button:

- No topics: 157 extracted blocks / 157 accepted.
- Basic mode, threshold 0.45, topic “bạn”: 52 accepted.
- “công việc” and “cong viec”: both 33 accepted.
- A longer query from the loaded conversation returned results and opened Detail.
- Final native screenshot shows the complete popup header, scrolling body and Scan footer. The extension was reloaded with the final build; the original topic “bạn” was restored.

Only aggregate results and local screenshots are retained. No private conversation text is committed. The accessibility interface truncates long text, so full equality of every private paragraph was not established; the complete-text assertions use synthetic fixtures and sampled public pages instead.

One Scan remained pending during iterative rebuilding/reloading and browser interaction. After the final reload, both the original keyword and longer query completed. The cause of that pending request is not conclusively isolated. A tested 15-second request timeout now prevents an indefinitely disabled Scan button; this is a mitigation, not proof that the underlying intermittent condition cannot recur.

## Remaining limits

- No claim of working on all websites: iframe documents, closed shadow roots, images/canvas text, restricted Chrome pages, unloaded/virtualized posts and collapsed content are outside the current scanner scope.
- Exact-match and Basic checks do not establish semantic AI quality. Real Ollama inference and audible pronunciation were not rerun in this repair; older reports remain separate.
- Closing the anchored popup stops its speech; use the explicit reader window for continued playback. Fullscreen/multiple-monitor OS behavior of that optional window is not exhaustively validated.
- Legacy Deep-scan controls do not expand or scroll the document. Vite/CRXJS still emits compatibility warnings despite passing production build and worker checks.
- PR #1 contains the earlier Local AI implementation; these repairs are prepared as a separate follow-up PR.
